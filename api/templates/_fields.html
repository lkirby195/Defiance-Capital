Required here means the minimum viable intake (SPEC §4.1) plus the closing date and the term, and the handful of actions that record a reason; the marker and the browser's own `required` attribute come from the same argument, so a box cannot look required and post empty. The marker is plain text in the label's own type - no weight, no colour. The attribute is a courtesy, not a control: `api/intake_form.py` checks the same list on the way in. `errors` is the other half of that courtesy. It comes from the render context rather than from an argument on every one of the forty call sites (`api/render.py` puts it there, and both forms import this file `with context`), and it is keyed by the same box names the macros below are called with — so a complaint about `purchase_price` lands under the Purchase Price box without anybody wiring it there. What is left at the top of the page is what is about more than one box and has nowhere else to go (`api/problems.py`). `readonly` is the other half of that: a box whose value is derived is shown rather than hidden, and posted back rather than dropped, but nobody is invited to argue with it. The server re-derives it either way. `mask` names the shape a box holds — `money`, `pct`, `phone` (`schema/masks.py`). The script in base.html formats what is typed into that shape, and the server parses the shape back out; neither depends on the other having run. `note` is a line under the box: what the number it holds comes to, or what it is measured against. The holding-cost percentage is the one that needs it — the box holds 2% and what a person wants to see is the dollars that is (SPEC §8.1). `default` is the config default for the four §8.1 economics that have one. The box is pre-filled with it and tagged, the tag goes as soon as somebody types something else, and the reset link puts it back.
